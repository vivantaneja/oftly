# Contributing

Set up the app using the README. Use Node 24 and Python 3.11 to match the verified development environment.

1. Create a focused branch.
2. Run the build and relevant tests. Scheduler/import changes need native collection tests; UI changes need browser journeys and desktop/mobile render checks.
3. Describe the behavior, verification and compatibility limits in the pull request.

Keep personal collections, media and coursework out of Git, reports and screenshots. Use synthetic fixtures and disposable collections. Do not start another process against the learner’s collection.

Preserve note IDs, card IDs, cloze ordinals and review history. Scheduling changes need versioned parameters and evidence beyond a prediction leaderboard. Distinguish research proposals from shipped behavior.

Follow the existing design system: keyboard access, visible focus, narrow layouts, larger text and reduced motion. No automatic AI upload or silent rewriting of cards.

Contributions are made available under AGPL-3.0-or-later. Retain notices for reused code.
